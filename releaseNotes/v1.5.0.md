* Centralized rate-limit handling for all Jira REST calls through a single Resilience4j-backed pipeline, replacing the per-service retry/parallel-stream code
  * Bounded concurrency: fixed worker pool replaces unbounded `parallelStream()` / `IntStream.parallel()` (default 4 in-flight requests)
  * Steady-state RPS limit (default 20 req/s) so a single run cannot saturate the tenant
  * Exponential backoff with jitter on retry; honors the server's `Retry-After` header (seconds and RFC-1123 date forms)
  * Detects Atlassian tenant-quota signals (`RateLimit-Reason: jira-quota-tenant-based` / `jira-quota-global-based`) and pauses every request for the run, aborting after repeated hits to avoid starving teammates and other clients on the same tenant
  * Every retry attempt and final exhaustion is now logged with attempt count, wait interval, and cause
* New optional configuration keys (defaults shown):
  * `rateLimit.maxConcurrent=4`
  * `rateLimit.requestsPerSecond=20`
  * `rateLimit.maxRetryAttempts=6`
  * `rateLimit.maxBackoffSeconds=60`
* Fixed `CommentsService.addCommentsToIssues` infinite recursion on rate-limited responses; per-issue comment failures are now logged and skipped instead of aborting the export
* Added support for Jira Cloud Deployment (v3 API)
